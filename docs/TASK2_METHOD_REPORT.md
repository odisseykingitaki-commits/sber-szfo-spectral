# Задача 2. Методологический отчёт: прогноз расходов и структурные сдвиги (СЗФО)

**Конкурс / проект:** спектральная синергетика экономических систем (СберИндекс)  
**Объект:** агрегаты расходов двух спектральных типов МО СЗФО (Task 1: 140/140)  
**Два уровня:** (A) многомодельный прогноз горизонтов 1 / 3 / 6 / 12 мес.; (B) поиск changepoints на спектральном сигнале  
**Репозиторий:** (локально / будет на GitHub)  
**Воспроизведение:** `conda activate sber && python src/12_timeseries.py && python src/13_changepoints.py` (см. `INSTALL.md` §4b)

Числа сверены с `results/forecast_all_models.csv`, `results/forecast_mae_post_leakage.md`, `results/changepoints_consensus.csv`, `results/TASK2_NOTES.md`, `results/dynamic_summary.json` (дамп после leakage-fix 2026-10-04).

Связь с Task 1: спектральная типология и окна динамики — **опциональный вход** (метки + `dynamic_summary`). Отчёт Task 2 читается самостоятельно; детали PLM — в `docs/TASK1_METHOD_REPORT.md`.

## 1. Постановка задачи

Нужны два связанных, но разных ответа по экономике расходов СЗФО:

1. **Прогноз** — насколько хорошо можно предсказать агрегированные расходы «сельского» и «городского» спектральных кластеров на горизонтах **1, 3, 6, 12** месяцев, и можно ли устойчиво обойти Prophet / naive.  
2. **Структурные сдвиги** — когда меняется коллективный спектральный режим системы (не «новостной календарь», а сигнал из окон Task 1).

Критерий конкурса «beat Prophet» трактуем **честно**: после фикса утечки **нет единого победителя**. Prophet часто лучший на городских; LGBM — на сельских H=3; naive конкурентоспособен на части горизонтов.

## 4. Уровень A — прогноз

### 4.1. Протокол

- Горизонты H ∈ {1, 3, 6, 12}: holdout = последние H месяцев.  
- Метрика **обязательная:** MAE. R2 — опционально (для H=1 в CSV пусто).  
- Канон: **`results/forecast_all_models.csv`**. Черновики `forecast_metrics*.csv` — игнорировать.

### 4.2. Анти-утечка (критично)

Был баг: `start_dt <= ds` подмешивал незавершённые / будущие окна.  
**Фикс:** спектральные фичи только из окон с **`end_dt < ds`** (окно полностью закончилось до даты прогноза).

```python
mask = spectral['end_dt'] < row['ds']
```

Бэкап до фикса: `results/_backup_pre_leakage_fix/`. После фикса «магический» вклад спектральных фич ослаб — это ожидаемо.

### 4.3. Модели

| Группа | Модели |
|--------|--------|
| Baselines | naive, seasonal, mean |
| Классика | Prophet |
| ML | LGBM, CatBoost (± Google Trends) |
| Foundation TS | **не использовались** (Chronos / TimesFM / MOIRAI) — см. §8 и `TASK2_GAPS.md` |

Фичи ML: лаги + прошлые спектральные статистики (+ Trends). При H=12 после `lag_12` точек мало → LGBM/CatBoost **пусты** в CSV (ограничение данных).

### 4.5. Кто выигрывает когда (честный нарратив)

| Ситуация | Победитель по MAE | Вывод |
|----------|-------------------|-------|
| Городские H=1,3,6 | **Prophet** | классика сильнее ML на этом ряде |
| Сельские H=3 | **LGBM** (1761) vs Prophet (1839) | единственный явный выигрыш ML над Prophet |
| Сельские H=1 | **seasonal** | сезонность бьёт всех |
| Сельские H=6 / городские H=12 | **naive** | baseline конкурентоспособен |
| Сельские H=12 | **Prophet** | длинный горизонт без ML |

**Итог:** единого «победителя конкурса» нет. Тезис «ML уверенно бьёт Prophet» **не подтверждается** post-leakage. Trends **не** стабильно помогают (часто `*_trends` хуже no-trends).

### 4.6. Реальный пример: сельские H=3

На горизонте 3 месяца для сельского кластера:

- **LGBM** MAE = **1761.44**  
- **Prophet** MAE = **1838.56**  
- **lgbm_trends** = 1801.60 (чуть хуже без Trends)  
- naive = 3133.21  

Это лучший аргумент «попробовали обойти Prophet» — локальный, не универсальный. На городских при том же H Prophet выигрывает с большим запасом (2653 vs LGBM 5241).

## 5. Уровень B — changepoints

### 5.1. Сигнал и дата

- Сигнал размерности 6: **`[λ₁…λ₅, PR₊]`**.  
- **Frustration не входит** в ruptures-сигнал (есть только в динамике Task 1).  
- Дата точки = **конец** скользящего окна (`spectral['date'] = end`).

### 5.2. Девять методов

| # | Метод | Параметры |
|---|-------|-----------|
| 1–3 | PELT | model ∈ {rbf, l2, normal}, pen=2 |
| 4–5 | Binseg | model ∈ {rbf, l2}, n_bkps=3 |
| 6 | BottomUp | rbf, n_bkps=3 |
| 7 | Window | rbf, width=5, n_bkps=3 |
| 8 | Dynp | rbf, n_bkps=3 |
| 9 | CUSUM_ARI | CUSUM по ряду ARI соседних окон |

### 5.3. «Лучший» ответ = консенсус ≥ 50%

Не crowним один алгоритм ruptures. Практический ответ жюри:

| Дата | Голоса | Доля | Консенсус |
|------|-------:|-----:|:---------:|
| **2024-09-01** | 7/9 | 77.8% | да |
| **2023-11-01** | 5/9 | 55.6% | да |
| **2024-04-01** | 5/9 | 55.6% | да |

Файлы: `changepoints_all_methods.csv`, `changepoints_consensus.csv`.

### 5.4. Пример интерпретации: 2024-09-01 (осторожно)

Окно w16: start **2024-04-01** → end **2024-09-01**.  
Соседи из `dynamic_summary.json`:

| Окно | Конец | PR₊ | Frustration |
|------|-------|----:|------------:|
| w15 | 2024-08-01 | 4.303 | 0.5625 |
| **w16** | **2024-09-01** | **4.267** | **0.5625** |

Консенсус 7/9 фиксирует **смену режима спектрального сигнала**, а не новостное событие. Мы **не** приписываем дату конкретным заголовкам СМИ (новостной пайплайн не строили). Для мониторинга полезно: осень 2024 — наиболее согласованный сдвиг среди трёх консенсусных дат.

Аналогично, 2023-11-01 (w6): PR₊ **4.352**, Frustration **0.625** — локальный пик participation ratio относительно соседних окон.

## 6. Внешний сигнал: Trends, не news

Критерий «интеграция новостей» (15%) **не закрыт**.

Что сделано:

- Google Trends как **прокси** внешнего интереса.  
- Корректное выравнивание: region avg → date merge; без подглядывания в будущие месяцы через spectral-rule.  

Ограничения:

- Один агрегат СЗФО на оба кластера.  
- После leakage-fix Trends часто **ухудшают** MAE.  
- Это не NLP по новостям.

Будущий news-пайплайн (без утечки): дата статьи → месяц → лаг 1–3 → merge только при `feature_date ≤ ds` → ablation vs Trends. См. `docs/TASK2_GAPS.md`.
