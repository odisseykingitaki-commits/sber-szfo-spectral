# Задача 2. Методологический отчёт: прогноз расходов и структурные сдвиги (СЗФО)

**Конкурс / проект:** спектральная синергетика экономических систем (СберИндекс)  
**Объект:** агрегаты расходов двух режимов потребления МО СЗФО (Тип A / Тип B, 140/140)  
**Два уровня:** (A) многомодельный прогноз горизонтов 1 / 3 / 6 / 12 мес.; (B) поиск changepoints на спектральном сигнале  
**Репозиторий:** локально, публикация — после конкурса

Отчёт Task 2 **самодостаточен**: жюри, читающее только этот документ, получает данные, определение типов A/B, постановку прогноза и changepoints. Подробнее о построении спектральной оси — опционально в `docs/TASK1_METHOD_REPORT.md`.

## 0. Постановка без Task 1

**Данные.** Базовый объект — помесячные расходы СберИндекса («Все категории») по муниципальным образованиям СЗФО: **280 МО**, **24 месяца** (2023–2024). Мобильность и прочие признаки используются лишь как контекст при построении режимов потребления; в прогнозе Task 2 таргет — агрегат расходов по кластеру × месяц. Росстат urov (доходы) в Task 2 **не** используется.

**Два кластера.** 280 МО агрегируются в **два режима потребления** (по **140** МО каждый). Кратко, как получены группы: по матрице признаков расходов строится оператор зависимостей (PLM), берётся **главная мода** спектра, проекция МО на неё (`U₁`) делится **медианой** — выше/ниже медианы → две равные группы. Это не «чёрный ящик из файла меток», а явный разрез по структуре трат. Опционально подробнее: `docs/TASK1_METHOD_REPORT.md`.

**Тип A / Тип B (сельский / городской паттерн потребления).**  
- **Тип A (сельский паттерн, cluster 0):** выше доля **grocery** (продовольствие в магазинах), ниже доли общественного питания и транспорта.  
- **Тип B (городской паттерн, cluster 1):** выше доли **food** (общепит) и **transport**, выше масштаб расходов.  
Ярлыки «сельский / городской» — удобная интерпретация контраста по структуре расходов, не юридический статус МО.

**Две самодостаточные подзадачи.**  
1. **Прогноз** — предсказать среднемесячные расходы агрегата Тип A и Тип B на горизонтах 1 / 3 / 6 / 12 месяцев; сравнить baselines, Prophet, ML (± Trends), foundation TS.  
2. **Changepoints** — найти даты смены режима на **спектральном сигнале**, построенном по скользящим окнам расходов (независимо от того, какая модель выигрывает по MAE).

**Спектральные ряды (определения для чтения без жаргона).** На каждом скользящем окне расходов (типично 6 месяцев) заново оценивается PLM → спектр. Из окна извлекаются:  
- **λ₁…λ₅** — ведущие собственные значения (масштабы согласованных направлений в признаках);  
- **PR₊** (participation ratio положительных мод) — насколько «размазана» положительная спектральная масса;  
- **Frustration** — доля отрицательных собственных значений (напряжённость / конфликтность структуры).  
В прогнозе используются прошлые окна (`end_dt < ds`); в сигнал changepoints входят **`[λ₁…λ₅, PR₊]`** (Frustration в ruptures **не** входит, но доступен в динамике для интерпретации).

## 1. Постановка задачи

Нужны два связанных, но разных ответа по экономике расходов СЗФО:

1. **Прогноз** — насколько хорошо можно предсказать агрегированные расходы Типа A (сельский паттерн) и Типа B (городской паттерн) на горизонтах **1, 3, 6, 12** месяцев, и можно ли устойчиво обойти Prophet / naive.  
2. **Структурные сдвиги** — когда меняется коллективный спектральный режим системы (не «новостной календарь», а сигнал из скользящих окон по расходам).

Критерий конкурса «превзойти Prophet» трактуем **строго**: после фикса утечки **нет единого победителя**. Prophet часто лучший на городских; LGBM — на сельских H=3; naive конкурентоспособен на части горизонтов.

## 4. Уровень A — прогноз

### 4.1. Протокол

- Горизонты H ∈ {1, 3, 6, 12}: holdout = последние H месяцев.  
- Метрика **обязательная:** MAE. R2 — опционально (для H=1 в CSV пусто).  
- Канон: **`results/forecast_all_models.csv`**. Черновики `forecast_metrics*.csv` — игнорировать.

### 4.2. Анти-утечка (критично)

Был баг: `start_dt <= ds` подмешивал незавершённые / будущие окна.  
**Фикс:** спектральные фичи только из окон с **`end_dt < ds`** (окно полностью закончилось до даты прогноза).

```python
mask = spectral['end_dt'] < row['ds']
```

Бэкап до фикса: `results/_backup_pre_leakage_fix/`. После фикса «магический» вклад спектральных фич ослаб — это ожидаемо.

### 4.3. Модели

| Группа | Модели |
|--------|--------|
| Baselines | naive, seasonal, mean |
| Классика | Prophet |
| ML | LGBM, CatBoost (± Google Trends) |
| Foundation TS | **Chronos-bolt-tiny** (zero-shot) — см. §4.7, §8 и `results/forecast_foundation.csv` |

Фичи ML: лаги + прошлые спектральные статистики (+ Trends). При H=12 после `lag_12` точек мало → LGBM/CatBoost **пусты** в CSV (ограничение данных).

### 4.5. Кто выигрывает когда (интерпретация)

| Ситуация | Победитель по MAE | Вывод |
|----------|-------------------|-------|
| Тип B H=1,3,6 | **Prophet** | классика сильнее ML на этом ряде |
| Тип A H=3 | **LGBM** (1761) vs Prophet (1839) | единственный явный выигрыш ML над Prophet |
| Тип A H=1 | **seasonal** | сезонность превосходит остальные модели |
| Тип A H=6 / Тип B H=12 | **naive** | baseline конкурентоспособен |
| Тип A H=12 | **Prophet** | длинный горизонт без ML |

**Итог:** единого «победителя конкурса» нет. Тезис «ML уверенно превосходит Prophet» **не подтверждается** post-leakage. Trends **не** стабильно помогают (часто `*_trends` хуже no-trends).

### 4.6. Реальный пример: Тип A, H=3

На горизонте 3 месяца для сельского паттерна (Тип A):

- **LGBM** MAE = **1761.44**  
- **Prophet** MAE = **1838.56**

Это единственный случай, где ML превосходит Prophet по MAE. На городском паттерне (Тип B) при H=3 Prophet выигрывает с большим запасом (2653 vs 5241).

## 5. Уровень B — changepoints

### 5.1. Сигнал и дата

- Сигнал размерности 6: **`[λ₁…λ₅, PR₊]`** — из скользящих окон PLM по расходам (§0).  
- **Frustration не входит** в ruptures-сигнал (хранится в динамике для интерпретации).  
- Дата точки = **конец** скользящего окна (`spectral['date'] = end`).

### 5.2. Девять методов

| # | Метод | Параметры |
|---|-------|-----------|
| 1–3 | PELT | model ∈ {rbf, l2, normal}, pen=2 |
| 4–5 | Binseg | model ∈ {rbf, l2}, n_bkps=3 |
| 6 | BottomUp | rbf, n_bkps=3 |
| 7 | Window | rbf, width=5, n_bkps=3 |
| 8 | Dynp | rbf, n_bkps=3 |
| 9 | CUSUM_ARI | CUSUM по ряду ARI соседних окон |

### 5.3. «Лучший» ответ = консенсус ≥ 50%

Не выделяем один алгоритм ruptures. Практический ответ жюри:

| Дата | Голоса | Доля | Консенсус |
|------|-------:|-----:|:---------:|
| **2024-09-01** | 7/9 | 77.8% | да |
| **2023-11-01** | 5/9 | 55.6% | да |
| **2024-04-01** | 5/9 | 55.6% | да |

Файлы: `changepoints_all_methods.csv`, `changepoints_consensus.csv`.

### 5.4. Пример интерпретации: 2024-09-01 (осторожно)

Окно w16: start **2024-04-01** → end **2024-09-01**.  
Соседи из `dynamic_summary.json`:

| Окно | Конец | PR₊ | Frustration |
|------|-------|----:|------------:|
| w15 | 2024-08-01 | 4.303 | 0.5625 |
| **w16** | **2024-09-01** | **4.267** | **0.5625** |
| w17 | 2024-10-01 | 4.162 | 0.5625 |

PR₊ снижается 4.303 → 4.267 → 4.162; Frustration стабилен ≈ 0.5625 на всех трёх окнах (`dynamic_summary.json`).

Консенсус 7/9 фиксирует **смену режима спектрального сигнала**, а не новостное событие. Мы **не** приписываем дату конкретным заголовкам СМИ (новостной пайплайн не строили). Для мониторинга полезно: осень 2024 — наиболее согласованный сдвиг среди трёх консенсусных дат.

Аналогично, 2023-11-01 (w6): PR₊ **4.352**, Frustration **0.625** — локальный пик participation ratio относительно соседних окон.

## 6. Внешний сигнал: Trends; попытка GDELT

Критерий «интеграция новостей» (15%) **не закрыт** выигрышем по MAE. Google Trends — прокси; плюс честная попытка GDELT.

Что сделано:

- Google Trends как **прокси** внешнего интереса (region avg → date merge).  
- **GDELT DOC API** (`timelinevol`, `sourcecountry:Russia`, 2023–2024): месячный intensity → z-score → `news_intensity_lag1` → merge к обоим кластерам (как Trends). Скрипт: `scripts/run_gdelt_task2.py` → `results/forecast_news.csv`.  

Ограничения:

- Один агрегат на оба кластера; гео **Russia-wide**, не СЗФО (keyword-фильтр NWFD слишком слабый).  
- После leakage-fix Trends часто **ухудшают** MAE.  
- `lgbm_news`: ΔMAE vs baseline LGBM = **0** на 6/6 клетках (feature importance news = 0 при тех же гиперпараметрах).  
- NLP по корпусу новостей СЗФО не строили; слайд «News: GDELT» не добавляли.

См. `docs/TASK2_GAPS.md` § GDELT attempt.
